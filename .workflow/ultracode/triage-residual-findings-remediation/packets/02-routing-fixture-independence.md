# Packet 02 — routing fixture independence

## Concern

Finding T2. Adversarial routing expectations are generated by the same evaluator
that is later checked against them, so a wrong route can be frozen as the
accepted baseline.

## Bounded questions

Establish, with `file:line` citations only, every `evaluate(...)` call that
writes `expected/`; the comparison logic in the validator; every invariant that
does not derive from a generated expectation; per-provider fixture inventory
with exact counts; the `live_guards` contents; whether expectations carry
generation provenance; and whether adversarial cases are distinguishable from
happy-path cases.

## Write scope

None. Read-only.

## Deliverable

`results/02-routing-fixture-independence.md`, ending with an
`INDEPENDENCE LEDGER` separating checks that survive an evaluator regression
from checks that silently follow it.
