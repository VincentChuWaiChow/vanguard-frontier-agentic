# Eval contract

## Goal
Prove the integration's repository correctness without overstating unavailable behavioral or runtime evidence.

## Success criteria
- Required IDs, companions, catalogs, fixtures, and adapters exist and obey repository schemas.
- Live changes never auto-dispatch and retain target, approval, rollback, and permission boundaries.
- Generated outputs and exports are current and self-contained.
- Required executed checks pass; non-executed model/live checks remain explicit blockers to promotion.

## Integration surfaces
`skills/istio`, `agents/istio`, the Kubernetes live guard, routing taxonomy/fixtures, catalogs, marketplace adapters, exports, model policy, tests, and asset integrity.

## Downstream consumers
Repository validators, native routing grader, marketplace exporters, supported harnesses, and release reviewers.

## Required checks
Bundle-to-repo traceability, adversarial routing cases, Istio structural/helper tests, native routing validation, standalone export resolution, catalog/schema/model checks, asset integrity, spell/Markdown gates, full validation, and remote SHA identity.

## Deliverables
Three packet reports, integration decision, final audit, and final report.

## Blocking conditions
Missing mandatory assets, safety bypasses, stale generated artifacts, failing required checks, dishonest classification of fixture checks, or absent actual LLM/live semantic evidence where promotion policy requires it.
