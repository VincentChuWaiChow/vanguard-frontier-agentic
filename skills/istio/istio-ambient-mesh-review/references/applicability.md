# Applicability and source discipline

Treat documentation as a starting hypothesis for the target environment, not proof of runtime behavior. Confirm the exact release, API/CRD version, mesh mode, installation method, controller, revision, object target, and enforcement point before issuing a version-sensitive conclusion.

Record a release-specific official source, section, retrieval date and any observed contradiction. URLs under `/latest/` can change; use them to discover the correct versioned documentation. Do not encode a floating "latest supported" version or claim CVE-free status from a cached support table.

When supplied code or controller status contradicts a document, preserve both observations, narrow the claim, and request the smallest discriminating check. Absence from a retrieved snippet is not proof that a feature does not exist.

Load only the reference needed for the current decision. Stop broad searches once evidence is sufficient for that decision. Keep references self-contained: do not reach into sibling skill folders during standalone use. Host permissions always outrank a skill's desired capabilities; these instructions are not a security sandbox.
