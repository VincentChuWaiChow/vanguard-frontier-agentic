# Draft a user story with separate completion policy

@jira-ticket-authoring

Draft one bounded Jira user story using the [story template](../assets/templates/story.md).

Explain who needs what outcome and why. Separate confirmed rules, proposals, dependencies, exclusions, and material unknowns. Write observable acceptance criteria with stable IDs and feasible verification; keep checks not run distinct from actual results.

Record the team's Definition of Done only when supplied, with its policy source and applicable evidence requirements. Do not make generic QA, sign-off, or deployment steps mandatory. A checklist does not authorize execution or prove completion.

Return the complete draft and activity-specific readiness verdict. Use **Unknown** for missing facts; do not create or update a Jira issue unless separately requested.

Input:
[Paste the user need, business rules, source links, existing acceptance IDs, target context, and team completion policy if available.]
