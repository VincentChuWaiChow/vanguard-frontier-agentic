# Break down an epic into independently ready children

@jira-ticket-authoring

Draft a coordinating Jira epic using the [epic template](../assets/templates/epic.md), then propose bounded child outcomes using the relevant bundled templates.

Explain the business outcome, scope, success measures, source evidence, shared interfaces, dependencies, and cross-ticket verification. Distinguish discovery from implementation and assess each child's readiness separately. An unsettled shared contract blocks only the children that depend on it.

Use local planning labels until actual Jira keys are available. Preserve known acceptance IDs, and do not invent people, dates, metrics, or configured work types. Closed child tickets alone do not prove the epic's business outcome.

Return complete drafts, a dependency order, and material questions. Use **Unknown** for missing facts. Do not create tickets or start implementation unless separately requested.

[Paste the desired outcome, requirements, constraints, existing tickets or IDs, interface evidence, dependencies, and relevant links.]
