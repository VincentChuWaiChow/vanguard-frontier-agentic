# Write release notes for business and technical readers

@confluence-document-authoring

Draft Confluence release notes for [release name or version].

Lead with customer and business impact. Organize the content into a release summary, new features, improvements, bug fixes, breaking changes, required user actions, and known issues. Remove sections that do not apply.

For each significant change, explain what changed, who is affected, and what the reader needs to do.

Use the supplied evidence to distinguish planned work, merged changes, deployed changes, and confirmed customer availability. State any unresolved availability or compatibility questions.

Include concise feature-use guidance where needed and a technical appendix for implementation details relevant to engineers.
